# XMAX x2 on the phone (2026-10-31)

Setup: app 1.6, module 1.4, game build 3.0.5364, Redmi Note 8. XMAX x2 imported from its original ZIP; a temporary probe (not released) counted `Monster` objects in the game's object manager after loading the same hero at the same spot. Nothing was saved.

## What x2 changes

- `records\xpack\game\gameengine.dbr`: `spawnMinModifier` and `spawnMaxModifier` 100 → 200 (twice as many monsters). The record is the PC version: it has 175 fields where the mobile one has 240, and it also changes inventory bag sizes (480×200 → 384×160), the potion stack limit (100 → 25), the experience formula (no difficulty bonus) and speed caps.
- Four boss pool records (Pharaoh's honour guard, Megalesios statue).

The mobile game uses the same record (`records\xpack\game\gameengine.dbr`, both modifiers 100), so x2 targets the right record.

## Result

| Mod selected | Monsters loaded around the hero |
|---|---|
| LootPlus (does not touch spawns) | 90 |
| XMAX x2 | 90 |

The count was the same in three readings per run. **x2 has no effect on the phone.** The game reads the game-engine record once at startup, before the loader activates mods when a character is loaded, so the mod's copy is never used. The same early caching explains the blank Masteries skill icons ([report](2026-10-31-masteries-coverage.md)).

Because the record is not used, its PC-only side effects (smaller bags, potion stacks) also do not appear. If mods are ever activated earlier, x2 would need a mobile-preserving version that changes only the two spawn fields.

## Next step

Activating mods before the engine reads its startup records (game engine, skill and mastery tables) would fix both problems. This is a change to when the loader runs, with its own risks for saved characters, and needs a separate investigation.
