# 7z import on the phone (app 1.1)

Date: 2026-10-31. Phone: Redmi Note 8, Android 16. App: Titan Quest Mods 1.1.

Many PC mods are published as 7z files. Until 1.0.1 the app asked players to repack them as ZIP on a computer. Version 1.1 reads them on the phone.

## How it works

[SevenZip.java](../android/src/org/tqmods/SevenZip.java) is a small 7z reader written for this project from the 7z format description and the LZMA specification (no third-party code). It converts the picked 7z file into a temporary ZIP, which then goes through the unchanged ZIP import: path checks, size limits, program-file refusal, variant choice.

- Methods: LZMA, LZMA2, Deflate and uncompressed (Copy); solid and non-solid archives; compressed or plain headers.
- Refused with a plain message: password-protected archives, filters such as BCJ2, and other methods (PPMd, BZip2).
- Every unpacked file is checked against the CRC stored in the archive; damaged or cut-off files are refused.
- Files the importer does not use (textures, images, readmes other than .txt/.md) are not unpacked: a block with only such files is skipped, so an unsupported method there does not matter.
- Limits: 512 MiB unpacked, 4,096 files, dictionary up to 256 MiB.

## Same mod added twice

Adding a mod that is already in the list used to create a second entry. Choosing it would start with a new copy of the characters, so progress made with the first entry seemed lost. Since 1.1 the app compares the files of the new entry with the existing ones (the app's own notes `.title` and `.kind` are ignored). For an identical mod it removes the new entry, chooses the existing one and says "This mod is already in the list". Checked on the phone with Masteries from 7z over the earlier ZIP import, and on the host with a different archive format and with a different mod.

## Smaller fix

After the Perf switch or another action that needs root, the list no longer jumps to the top. Checked on the phone: the list stays in place while Perf is switched on and off.
